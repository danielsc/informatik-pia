Expressions

An expression produces a value

Try in Thonny · Predict, then test each expression


2 + 3
9 - 4
3 * 4

0.5 + 0.25
"Pi" + "co"
"ha" * 3

Think like the interpreter

  1. Read the values.
  2. Apply the operator.
  3. Produce one result.

Predict: Which results are floats or strings? Does the last line give 14 or 20?

Take the eight examples one at a time: predict the value and type, then run the line in the Shell. Results: 5 (int), 5 (int), 12 (int), 5.0 (float), 0.75 (float), "Pico" (str), "hahaha" (str), 14 (int). The + operator adds numbers but joins strings; * multiplies numbers but repeats a string. Division / produces a float, even for 10 / 2. Multiplication happens before addition: compare the last line with (2 + 3) * 4, which gives 20. The goal is to see how values and operators form expressions, not to memorise every Python operator.

Errors are evidence

Read the last line first

Try in Thonny · Make this typo on purpose


>>> pritn("Hello")
Traceback (most recent call last):
  File "<stdin>", line 1
NameError: name 'pritn' is not defined

1 · Name it

NameError

2 · Locate it

Line 1

3 · Compare it

pritn versus print

Change only pritn to print, then run it again. If it works, the misspelling caused the error.

Create the typo live. Model calm debugging language: symptom, evidence, suspected cause, one change, rerun. Ask why changing only one thing gives clearer evidence. If useful, also show a missing quote. Do not use 10 / 0 as the first error because the typo is easier to act on. Meet your hardware

What is the Raspberry Pi Pico?

Watch and discuss · Keep USB unplugged for now

A tiny computer for electronics

The Pico is a microcontroller board: a small computer that runs your program to control electronic components.

We program it in Python

We write code in Thonny. The Pico runs it using MicroPython, a version of Python for microcontrollers.

It can sense and act

Through its connection pins, it can read buttons and sensors, control LEDs, and make sounds. Today: switch a light on and off.

Hand out the Picos now, not earlier. Hold up an unplugged Pico and compare it with the picture. Point out the USB connector, onboard LED, and connection pins; students do not need to memorise the pin labels. The board contains a microcontroller chip that runs the program. Unlike a desktop computer, it is designed to control electronics rather than run desktop applications. MicroPython is already installed on the prepared boards. Buttons, sensors, and sound come later; today starts with the onboard LED, which needs no external wiring. External components need the appropriate safe circuit, not arbitrary direct connections. Keep USB disconnected until the next slide.

Hardware vocabulary

Three lines connect Python to the Pico

Pin

Gives Python access to a Pico pin.

"LED"

Names the onboard LED.

Pin.OUT

Says the pin sends a signal out.


from machine import Pin
led = Pin("LED", Pin.OUT)
led.on()

These lines are already in 01_hello_pico.py; you do not need to learn them by heart. Think about the program you just ran: What changed on the screen, and what changed on the Pico?

Avoid teaching object-oriented vocabulary. “led is our useful name for the output” is enough. Demonstrate led.on() and led.off() in the Shell if the connection is stable. Expected explanation: import Pin, use led as the name for the onboard LED output, then switch it on with led.on(). Why names matter

One edit can change every use

Experiment

Inside a breadboard

Which holes are already connected?

Watch and discuss · USB stays unplugged

1: five holes share a strip; the next column is separate. 2: no internal connection across the channel. 3: each rail row is separate.

Markings show hidden metal, not added wires. Rails are not powered by their colour; check for splits while unplugged.

Use the template breadboard image and match its numbered markings to the real board. Trace f–j vertically in one column, then a–e across the channel: these are separate metal strips. Adjacent columns are separate too. Trace one long rail row, not both rows together; top and bottom rail banks are also separate. Markings represent hidden connections, not jumper cables. Rail splits vary: inspect the actual board and check continuity only while unplugged. A resistor must bridge different groups. No power yet; do not join 3.3 V and VBUS.

Use the resistor

GP15 must reach the ordinary LED through 220 Ω.

Check orientation

Long leg/anode toward the resistor; short leg/flat edge toward GND.

What ON and OFF mean

Why the LED lights

Discuss · Trace the complete circuit

led.on()
GP15 becomes 3.3 V
→
Current flows
resistor protects LED
→
LED lights
then current reaches GND
led.off()
GP15 becomes 0 V
→
No voltage difference
current stops
→
LED is dark

In the copied program, change only Pin("LED", Pin.OUT) to Pin(15, Pin.OUT).

This is conceptual, not a full electricity lesson. ON makes GP15 high, creating a voltage difference between GP15 and GND. Conventional current flows through the resistor and correctly oriented LED. OFF brings GP15 close to GND, so there is no useful voltage difference. Ask why the resistor is still necessary and what a reversed LED would do.

Debugging physical systems

Code, circuit, or assumption?

Discuss · Choose one exact check for each column

Code

Wrong pin? Misspelled name? Program still running?

Circuit

LED reversed? Wire one row away? Missing resistor?

Assumption

Did we predict the wrong output or inspect the wrong LED?

If the external LED stays dark: first run the known-working onboard-LED file. If that works, download and run the GP15 ON/OFF test. If GP15 still does not light the LED, stop, unplug USB, and check the circuit against the diagram.

Walk through the decision sequence. If the onboard LED file fails, inspect the Thonny interpreter, USB connection, and running program before touching the circuit. If the known GP15 test fails after the onboard test succeeds, stop and unplug before checking LED orientation, resistor placement, GP15, and GND. Do not change code and wiring simultaneously.

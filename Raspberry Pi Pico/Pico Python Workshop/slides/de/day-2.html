01

Teil 1 · Beginnt mit Werten

Welche Art von Wert speichert Python?

Bevor ein Programm entscheiden kann, braucht es Werte in Formen, die Python versteht.

Leiten Sie diesen Abschnitt zunächst an. Benennen Sie die Typen in verständlicher Sprache, bevor Boolean-Werte als eigene Idee folgen.

Arten von Werten

Ganze Zahlen und Dezimalzahlen haben verschiedene Aufgaben

Anschauen und besprechen · Sagt, was jede Zeile speichert


raw_value = 32768
fraction = raw_value / 65535

print(type(raw_value))
print(type(fraction))

int

Eine ganze Zahl wie 32768. Nützlich für Anzahlen, Pin-Nummern und viele Sensorwerte.

float

Eine Zahl mit Dezimalteil, zum Beispiel das Ergebnis einer Division.

Verknüpfen Sie raw_value mit dem späteren Potentiometer-Messwert. Führen Sie bool hier noch nicht ein; es folgt als Antwort auf eine Frage.

Casting

Manchmal braucht ihr einen neuen Wert eines anderen Typs

In Thonny ausprobieren · Führt die Zeilen aus und prüft jedes Ergebnis


raw_value = 32768
fraction = raw_value / 65535
percent = int(fraction * 100)

print(fraction)
print(percent)
print(type(percent))

Casting bedeutet, dass Python einen neuen Wert in einer anderen Form erzeugt. Hier entfernt int(...) den Dezimalteil.

Die Klasse soll erklären, dass percent eine ganze Zahl aus dem berechneten Dezimalwert ist. Das bereitet die Helligkeitsschwellen ohne Hardware vor.

Teil 2 · Stellt eine Frage

Python kann erst entscheiden, wenn eine Frage wahr oder falsch wird

Vergleiche erzeugen Boolean-Werte. Diese steuern später die Entscheidungen im Code.

Wechseln Sie ausdrücklich von Zahlentypen zu Fragen über Werte. Die nächsten Folien erklären Boolean-Werte, Vergleichsoperatoren, Zuweisung im Gegensatz zu Gleichheit und not.

Boolean-Werte

Ein Vergleich stellt eine Frage mit zwei möglichen Antworten

In Thonny ausprobieren · Sagt das Ergebnis vor Run voraus


score = 347

print(score < 350)
print(score >= 350)
print(score == 347)

True

Die Aussage stimmt.

False

Die Aussage stimmt nicht.

Vergleich

<, >= und == vergleichen Werte und erzeugen eine Boolean-Antwort.

Fragen Sie jeweils nach einer genauen Ausgabezeile. Gehen Sie erst weiter, wenn klar ist: Vergleiche erzeugen Werte, nicht nur Aktionen.

Eine häufige Verwechslung

= speichert; == fragt, ob zwei Werte gleich sind

Anschauen und besprechen · Lest jede Zeile laut in Worten

CodeSo könnt ihr es lesen …Aufgabe
reaction_ms = 412„Speichere 412 in reaction_ms.“Zuweisung
reaction_ms == 412„Ist reaction_ms gleich 412?“Vergleich
reaction_ms != 412„Ist reaction_ms ungleich 412?“Vergleich

Mit = speichert ihr. Mit == fragt ihr „gleich?“ und mit != „ungleich?“

Sprechen Sie diese typische TEALS-Verwechslung direkt an: „speichert einen Wert“ im Gegensatz zu „stellt eine Frage“. Verzweigungen folgen erst nach der active-low-Eingabe auf der eigenen if/elif/else-Folie.

not und active-low-Eingabe

Beim Tastendruck wird der elektrische Wert niedrig

Auf Papier · Füllt vor dem Prüfen die letzte Spalte aus

Active-low bedeutet: Das wichtige Ereignis setzt das Signal auf niedrig. not macht aus dem Messwert eine verständliche Python-Antwort.

Die Position des Pull-up-Widerstands ist noch nicht nötig. Wichtig ist: losgelassen ergibt 1, gedrückt ergibt 0. Die spätere Aufbaufolie zeigt warum.

Einen Zweig wählen

if, elif und else wählen einen Pfad

Anschauen und besprechen · Welcher Zweig läuft bei 10 %, 45 % und 92 %?


if percent < 20:
    led.duty_u16(0)
elif percent <= 70:
    led.duty_u16(20000)
else:
    led.duty_u16(65535)

Python prüft von oben nach unten und führt nur den ersten Zweig aus, dessen Bedingung True ist.

Genau diese Struktur nutzt die Klasse nach dem Potentiometer-Aufbau. Fragen Sie nach Zweig und LED-Verhalten, nicht nur nach dem Wort true.

Notieren

Konkrete Testreihenfolge

  1. Dreht den Knopf nahe 0 % und prüft, dass die LED aus ist.

Teil 5 · Merken und wiederholen

Nutzt Listen und Abbruchbedingungen für ein Spiel

Ein Reaktionsspiel braucht mehrere Ergebnisse. Jede Schleife muss wissen, wann sie endet.

Dieser Abschnitt bereitet den selbst ergänzten Starter vor. Betonen Sie die Wirkung jedes Listenwerkzeugs und jeder while-Bedingung, nicht das Auswendiglernen.

Listen

Eine Liste kann mehrere Reaktionszeiten speichern

In Thonny ausprobieren · Führt jede Zeile aus und erklärt das Ergebnis


times = [410, 375, 522]
print(times[0])
times.append(330)
print(len(times))
print(min(times))
print(times[-1])

Index

times[0] fragt nach dem ersten Element.

Append

append fügt am Ende ein neues Ergebnis hinzu.

len

len(times) zählt die gespeicherten Ergebnisse.

min

Mit diesem eingebauten Werkzeug findet ihr heute das schnellste Ergebnis.

TEALS behandelt Listen, Indizes, append und len. Stellen Sie min als praktische Workshop-Ergänzung vor und nutzen Sie es nach Ende der Spielschleife.

Plant zuerst das Spiel

Bringt eine Runde in die richtige Reihenfolge, bevor ihr tippt

Auf Papier · Nummeriert die Schritte vom ersten bis zum letzten

Öffnen

03_reaction_game_starter.py

Importe, Pin-Einrichtung, scores = [] und sicheres Ausschalten der LED sind vorgegeben.

Eine Runde in der richtigen Reihenfolge

  1. Wartet, bis der Taster losgelassen ist.
  2. Wartet eine zufällige Anzahl Millisekunden.
  3. Schaltet die LED ein und speichert die Startzeit.
  4. Wartet, bis der Taster gedrückt wird.
  5. Berechnet reaction_ms und schaltet die LED aus.
  6. Fügt das Ergebnis zu scores hinzu.
  7. Gebt eine Meldung zum Ergebnis aus.
Bleiben Sie konkret: Die Klasse ordnet die genauen Schritte aus den Kommentaren des Starters, statt einen vagen Ablauf zu erfinden. Das vorgegebene Gerüst bleibt stehen.

Starter ausbauen

Ersetzt pass durch funktionierende Spiellogik

In Thonny ausprobieren · Bringt erst eine Runde zum Laufen, dann alle drei

Schreibt diese Teile

  1. Löscht innerhalb von try: das Wort pass.
  2. Schreibt mit den beiden Wartevorgängen eine funktionierende Runde.
  3. Fügt scores.append(reaction_ms) hinzu.
  4. Ergänzt if reaction_ms < 350 → Quick!, sonst Keep practising!.
  5. Umschließt die Runde mit while len(scores) < ROUNDS:.

Nutzt die vorgegebenen Werkzeuge wie gezeigt


wait_ms = randint(1000, 3000)
sleep_ms(wait_ms)
start_ms = ticks_ms()
end_ms = ticks_ms()
reaction_ms = ticks_diff(end_ms, start_ms)

Timing-Werkzeuge und das sichere Aufräumen mit try/except/finally sind vorgegeben. Heute konzentriert ihr euch auf die Spiellogik darin.

Dies ist die zentrale selbstständige Programmierfolie. Lassen Sie die Klasse nach einer glaubwürdigen Reaktionszeit anhalten, bevor die äußere Schleife folgt.

Ergebnis prüfen

Testet das Spiel mit vorzeigbaren Belegen

Schaltung testen · Führt die vollständige Version mit drei Runden aus

Euer Programm sollte zeigen

  1. Die LED wartet und schaltet sich dann ein.
  2. Ein Tastendruck erzeugt eine ganzzahlige Reaktionszeit.
  3. Jede Runde gibt Quick! oder Keep practising! aus.
  4. Nach drei Runden gibt die Shell die Liste und mit min(scores) das schnellste Ergebnis aus.

Nützliche Prüfungen bei Fehlern

  1. Geht die LED nie an, gebt wait_ms aus und prüft, ob das Programm noch wartet.
  2. Erkennt das Spiel keinen Tastendruck, testet den Taster erneut mit 01_button_decisions.py.
  3. Wirkt ein Ergebnis unmöglich, gebt für eine Runde start_ms und reaction_ms aus.
Halten Sie die Fehlersuche konkret und schrittweise: zuerst Timing, dann die bekannte funktionierende Verkabelung, danach die berechneten Werte. Vermeiden Sie vage Aufforderungen wie „kleiner testen“.

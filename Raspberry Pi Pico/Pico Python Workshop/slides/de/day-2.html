Teil 1 · Beginnt mit Werten

Welche Art von Wert speichert Python?

Bevor ein Programm entscheiden kann, braucht es Werte in Formen, die Python versteht.

Leiten Sie diesen Abschnitt zunächst an. Benennen Sie die Typen in verständlicher Sprache, bevor Boolean-Werte als eigene Idee folgen.

Arten von Werten

Ganze Zahlen und Dezimalzahlen haben verschiedene Aufgaben

Anschauen und besprechen · Sagt, was jede Zeile speichert


raw_value = 32768
fraction = raw_value / 65535

print(type(raw_value))
print(type(fraction))

int

Eine ganze Zahl wie 32768. Nützlich für Anzahlen, Pin-Nummern und viele Sensorwerte.

float

Eine Zahl mit Dezimalteil, zum Beispiel das Ergebnis einer Division.

Verknüpfen Sie raw_value mit dem späteren Potentiometer-Messwert. Führen Sie bool hier noch nicht ein; es folgt als Antwort auf eine Frage.

Casting

Manchmal braucht ihr einen neuen Wert eines anderen Typs

raw_value = 32768
fraction = raw_value / 65535
percent = int(fraction * 100)

print(fraction)
print(percent)
print(type(percent))

Casting bedeutet, dass Python einen neuen Wert in einer anderen Form erzeugt. Hier entfernt int(...) den Dezimalteil.

Die Klasse soll erklären, dass percent eine ganze Zahl aus dem berechneten Dezimalwert ist. Das bereitet die Helligkeitsschwellen ohne Hardware vor.

Teil 2 · Stellt eine Frage

Python kann erst entscheiden, wenn eine Frage wahr oder falsch wird

Vergleiche erzeugen Boolean-Werte. Diese steuern später die Entscheidungen im Code.

Wechseln Sie ausdrücklich von Zahlentypen zu Fragen über Werte. Die nächsten Folien erklären Boolean-Werte, Vergleichsoperatoren, Zuweisung im Gegensatz zu Gleichheit und not.

Boolean-Werte

Ein Vergleich stellt eine Frage mit zwei möglichen Antworten

In Thonny ausprobieren · Sagt das Ergebnis vor Run voraus


score = 347

print(score < 350)
print(score >= 350)
print(score == 347)

True

Die Aussage stimmt.

False

Die Aussage stimmt nicht.

Vergleich

<, >= und == vergleichen Werte und erzeugen eine Boolean-Antwort.

Fragen Sie jeweils nach einer genauen Ausgabezeile. Gehen Sie erst weiter, wenn klar ist: Vergleiche erzeugen Werte, nicht nur Aktionen.

Eine häufige Verwechslung

= speichert; == fragt, ob zwei Werte gleich sind

Anschauen und besprechen · Lest jede Zeile laut in Worten

CodeSo könnt ihr es lesen …Aufgabe
reaction_ms = 412„Speichere 412 in reaction_ms.“Zuweisung
reaction_ms == 412„Ist reaction_ms gleich 412?“Vergleich
reaction_ms != 412„Ist reaction_ms ungleich 412?“Vergleich

Mit = speichert ihr. Mit == fragt ihr „gleich?“ und mit != „ungleich?“

Sprechen Sie diese typische TEALS-Verwechslung direkt an: „speichert einen Wert“ im Gegensatz zu „stellt eine Frage“. Verzweigungen folgen erst nach der active-high-Eingabe auf der eigenen if/elif/else-Folie.

Boolean-Antworten umkehren

not kehrt eine Boolean-Antwort um

In Thonny ausprobieren · Jede Antwort vor Run vorhersagen


print(not True)
print(not False)
ready = True
print(not ready)

not True ist False; not False ist True. Bei digitalen Messwerten wirkt 0 wie falsch und 1 wie wahr.

not vor Hardware- und Schleifenbeispielen definieren. Erwartet False, True, False. Ein digitaler Pin liefert den Integer 0 oder 1, kein bool-Objekt; not erzeugt einen Boolean-Wert.

Active-high: Der Druck setzt GP13 auf 3.3 V. Der externe 10-kΩ-Pull-down zu GND sorgt losgelassen für 0. Nutzt button.value() == 1 für „gedrückt“.

Erst Antworten notieren, dann Fragmente aufdecken. Losgelassen: not 0 ist True, also nicht gedrückt. Gedrückt: not 1 ist False. Der Taster verbindet GP13 beim Druck mit 3.3 V; der externe 10-kΩ-Widerstand verbindet GP13 mit GND. Die Aufbaufolie zeigt die Schaltung.

Zwei Bedingungen gemeinsam

and braucht zwei wahre Antworten

In Thonny ausprobieren · Vorhersagen, dann einen Wert ändern


waiting = True
pressed = False
print(waiting and not pressed)

Die Antwort ist nur True, solange wir noch warten und der Taster nicht gedrückt ist. Ändert pressed zu True: Die gemeinsame Antwort wird False.

and vor der überwachten Wartezeit im Reaktionsspiel erklären. Beide Bedingungen müssen gelten; sobald eine falsch wird, endet eine while-Schleife. Später beantwortet die vorgegebene Timing-API, ob die zufällige Wartezeit noch läuft.

Einen Zweig wählen

if, elif und else wählen einen Pfad

Anschauen und besprechen · Welcher Zweig läuft bei 10 %, 45 % und 92 %?


if percent < 20:
    led.duty_u16(0)
elif percent <= 70:
    led.duty_u16(20000)
else:

Python prüft von oben nach unten und führt nur den ersten Zweig aus, dessen Bedingung True ist.

Regeln des Reaktionsspiels

Auf das Licht warten — dann reagieren!

Anschauen und besprechen · Eine faire Runde ohne Code üben

1 · Bereitmachen

Taster loslassen. Die LED bleibt eine zufällige Zeit aus. Noch nicht drücken.

2 · Los!

Sobald die LED leuchtet, so schnell wie möglich drücken. Gemessen wird vom Einschalten bis zum Druck.

3 · Fehlstart

Ein Druck vor dem Licht ist ein False start! Kein Ergebnis wird gespeichert. Loslassen und die Runde erneut versuchen.

Sammelt drei gültige Zeiten. Weniger Millisekunden bedeuten eine schnellere Reaktion. Sagt voraus, was bei einem Druck während der dunklen Wartezeit passiert.

Spiel vor der Umsetzung erklären. Fairen Druck und Fehlstart zeigen. Frühe Tastendrücke müssen während der Wartezeit erkannt werden, statt als Nullzeit-Erfolg zu zählen. Nur gültige Runden zählen zu ROUNDS.

Plant zuerst das Spiel

Bringt eine Runde in die richtige Reihenfolge, bevor ihr tippt

Auf Papier · Nummeriert die Schritte vom ersten bis zum letzten

Öffnen

03_reaction_game_1_starter.py

Importe, Pin-Einrichtung, scores = [] und sicheres Ausschalten der LED sind vorgegeben.

Schritte zum Ordnen

  • Wartet eine zufällige Zeit und prüft dabei auf frühen Druck.
  • Wartet, bis der Taster losgelassen ist.

Bleiben Sie konkret: Die Klasse ordnet die genauen Schritte aus den Kommentaren des Starters, statt einen vagen Ablauf zu erfinden. Erster Teil: loslassen, überwacht warten, Fehlstart-Zweig, LED und Startzeit. Gültigen Zweig auf der nächsten Folie fortsetzen. Das vorgegebene Gerüst bleibt stehen.

Gültiges Ende planen

Was passiert nach dem Einschalten?

Auf Papier · Vier Schritte nach einem gültigen Start ordnen

  • Gültiges Ergebnis zu scores hinzufügen.
  • Eine Meldung zum Ergebnis ausgeben.
  • Warten, bis der Taster gedrückt wird.
  • reaction_ms berechnen und LED ausschalten.

Ein Fehlstart nimmt diesen Weg nicht. Er gibt False start! aus, speichert nichts und wiederholt die Runde.

Erwartet: auf Druck warten, berechnen und ausschalten, speichern, Meldung. Mit dem ersten Planungsteil verbinden. Nur der gültige Zweig speichert eine Reaktionszeit.

Timing-API-Rezept

Warten — aber den Taster weiter prüfen

Anschauen und besprechen · Die mit and verbundenen Bedingungen erklären


wait_ms = randint(1000, 3000)
wait_started_ms = ticks_ms()
while (
    ticks_diff(ticks_ms(), wait_started_ms)
    < wait_ms and not button.value()
):
    sleep_ms(1)

Warten, solange Zeit bleibt und kein Druck erfolgt. Danach button.value() prüfen: Fehlstart oder gültiger Start? Mit ticks_ms() und ticks_diff(end_ms, start_ms) einen gültigen Druck messen.

Timing-Ausdruck als zwei mit and verbundene Bedingungen lesen. Ein einzelnes sleep_ms(wait_ms) übersieht frühe Tastendrücke. Vorgegebenes API-Rezept wiederverwenden; Fehlstart-Zweig und Spiellogik schreibt die Klasse selbst.

Starter ausbauen

Ersetzt pass durch funktionierende Spiellogik

In Thonny ausprobieren · Erst eine Runde, dann alle drei

  1. Innerhalb von try: pass löschen; finally behalten.
  2. Eine Runde mit überwachter zufälliger Wartezeit schreiben.
  3. Bei Fehlstart False start! ausgeben; nur gültige Runden verwenden scores.append(reaction_ms).
  4. if reaction_ms < 350 → Quick!, sonst Keep practising! ergänzen.
  5. Runde mit while len(scores) < ROUNDS: umschließen.
Dies ist die zentrale selbstständige Programmierfolie. Lassen Sie die Klasse nach einer glaubwürdigen Reaktionszeit und einem abgewiesenen Fehlstart anhalten, bevor die äußere Schleife folgt. Vorgegebenes Aufräumgerüst behalten.

Ergebnis prüfen

Testet das Spiel mit vorzeigbaren Belegen

Schaltung testen · Führt die vollständige Version mit drei Runden aus

Euer Programm sollte zeigen

  1. Die LED wartet und schaltet sich dann ein.
  2. Ein Druck nach dem Licht erzeugt eine ganzzahlige Reaktionszeit. Ein früher Druck gibt False start! aus und speichert kein Ergebnis.
  3. Jede Runde gibt Quick! oder Keep practising! aus.
  4. Nach drei Runden gibt die Shell die Liste und mit min(scores) das schnellste Ergebnis aus.

Nützliche Prüfungen bei Fehlern

  1. Geht die LED nie an, gebt wait_ms aus und prüft, ob das Programm noch wartet.
  2. Erkennt das Spiel keinen Tastendruck, testet den Taster erneut mit 01_button_decisions.py.
  3. Wirkt ein Ergebnis unmöglich, gebt für eine Runde start_ms und reaction_ms aus.
Halten Sie die Fehlersuche konkret und schrittweise: zuerst Timing, dann die bekannte funktionierende Verkabelung, danach die berechneten Werte. Vermeiden Sie vage Aufforderungen wie „kleiner testen“.
